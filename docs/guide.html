1. The tournament format

Instead of McMahon scores, every player has a tournament rating (TGoR):

  • Start: the TGoR starts at the player's current EGD GoR on registration day. Players without a GoR start at the value of their declared rank (1k = 2000, 1d = 2100, 100 points per rank). The director may correct a starting GoR, for example when it is clearly outdated.
  • After every round, all TGoRs are updated with the EGD rating formula, with two changes. The formula's con factor is multiplied by the tournament's k-factor, so ratings move faster than in the EGD. The EGD's anti-deflation bonus is not used. All games of a round are rated from the TGoRs before that round.
  • Pairing: players are paired so that the TGoR differences are as small as possible, using the blossom algorithm. Two players never meet twice through automatic pairing, and pairs from the same club are avoided where possible.
  • Handicap: games are played with full handicap by default, one stone per 100 TGoR points of difference. A reduction ("full minus N") can be set. Players may agree on a different handicap for their game.
  • Winner: the player with the highest final TGoR wins. If two players have the same final TGoR, the one with the lower starting GoR ranks higher. If that is also equal, a random draw decides.

Each step reads and writes LibreOffice Calc files (.ods). You can open, check and change them by hand between the steps. The files are the only record of the tournament: there is no hidden database.

All files of one tournament live in one folder:

my_tournament/
  tournament.toml     settings                                   (step 1)
  players.ods         registered players                          (step 2)
  round_1.ods         pairing of round 1; results are entered here (steps 3, 4)

All commands take the option -d <folder> to choose the tournament folder. Without it, the current folder is used. So you can either cd my_tournament once, or add -d my_tournament to every command.

3. Installation AVAILABLE

The tools need Python 3.11 or newer. On Ubuntu also install python3-venv and python3-tk (the latter for the registration window):

sudo apt install python3-venv python3-tk
cd ~/Go/TournamentOrgaTool
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
source .venv/bin/activate        # afterwards 'gotourney' is available in this terminal
gotourney --help

Alternatively, pipx install -e ~/Go/TournamentOrgaTool makes gotourney available in every terminal without activating anything.

4. Setting up a tournament AVAILABLE

gotourney init my_tournament --name "21. Schweriner Drachenschlacht" --rounds 5

5. Registering players

5.1 The registration window AVAILABLE

gotourney gui -d my_tournament
  1. Search: type part of the name in the search field. Name parts can be in any order ("erik broek" finds van den Broek Erik) and umlaut spellings are treated alike ("Lüthke" finds Luethke). Typing digits searches by EGD PIN. Players who are already registered are marked (registered).
  2. Choose a player: press ↓ and Enter, or double-click. Enter in the search field takes the first match. The form is filled with name, rank, GoR, PIN, country and club. The window then fetches the player's latest data live from the EGD and updates the GoR if it changed.
  3. Check and complete the form: untick rounds the player will not play, tick Joker if the player may sit out odd rounds, and add notes. Hints in orange appear under the form for:
    • a PIN that is already registered;
    • a rank and GoR that differ by more than rank_gor_tolerance;
    • a last EGD tournament older than gor_outdated_years, meaning the GoR may be outdated. Correct the GoR field if needed.
  4. Add player (or Enter in a form field) writes the player to players.ods immediately.
  • Players who are not in the EGD: type their data into the form without searching. A rank is enough: the GoR is then taken from the rank.
  • Editing: click a player in the bottom table. The form switches to Edit ID n. Use Save changes or Remove player. New / clear goes back to adding.
  • Check registration runs the registration check (see 5.4).
  • Update EGD list downloads a fresh copy of the EGD player list.
The EGD player list. Searching uses a local copy of the complete EGD player list (about 56,500 players). It is stored in ~/.cache/gotourney/ and downloaded again when it is more than a day old. If there is no internet at the venue, the last downloaded list is used. Run gotourney egd update the evening before the tournament to be safe.

5.2 Registering on the command line AVAILABLE

gotourney players add --pin 10774412                       # everything else from the EGD
gotourney players add --pin 20633162 --gor 2500 --rounds 1-3
gotourney players add Doe John --rank 5k --club HH --country DE --joker
gotourney players list
gotourney egd search "luethke h"                           # find a PIN

Options of players add: --rank, --gor, --pin, --country, --club, --rounds (all, none, 1,2,4, 1-3), --joker, --notes. Values you give explicitly win over the EGD data.

5.4 Checking the registration AVAILABLE

gotourney players check

Problems are reported at three levels:

  • Errors must be fixed before pairing:
    • the same PIN registered twice;
    • a player with neither GoR nor rank;
    • a round with an odd number of players and no joker. Nominate a joker by marking one of that round's players in the Joker column.
  • Warnings should be checked: rank and GoR far apart, GoR possibly outdated, a player registered for no round, two players with the same name.
  • Info is for your knowledge only, for example which jokers can sit out in odd rounds.

The command ends with an error status if there are errors, so it can also be used in scripts.

5.5 Refreshing EGD data AVAILABLE

gotourney players sync              # live from the EGD
gotourney players sync --offline    # only the downloaded player list

Fetches the current EGD data for all registered players and reports what changed: name, country, club, EGD GoR and last tournament. The declared rank is never changed. The GoR column (starting TGoR) is only filled when it is empty, so your corrections are never overwritten. Once round 1 has been paired, the starting GoRs are frozen.

6. Pairing a round AVAILABLE

6.1 Workflow

  1. Optional – manual pairings first. If you want to fix certain games yourself (for example a rematch, or players who must play early), run gotourney pair 3 --template. It creates an empty round_3.ods. Enter those boards with the two player IDs and mark them x in the Manual column. The sheet Participants lists the players of the round with their TGoR to help you. If you leave Handicap empty, the default handicap, komi and colours are filled in (White and Black may be swapped so that the weaker player gets black). If you enter a handicap, your colours and handicap are kept as they are. Manual pairings may be rematches; you get a warning.
  2. Automatic pairing: gotourney pair 3 keeps all boards marked x in the Manual column and pairs all remaining players of round 3. Boards without the mark are paired again, so running pair twice gives a fresh pairing.
  3. Check and print round_3.ods. Players may agree on a different handicap; just change the Handicap/Komi cells of that board. The tools always use what is written in the file.
gotourney pair refuses to overwrite a round file that already contains results. Use --force only if you really want to pair the round again. A round can only be paired when all results of the previous rounds are entered, and not after a later round exists.

6.2 How the automatic pairing works

  • Participants: the players with an x in this round's column who are not on a manual board.
  • Odd number of players: one joker sits out, namely the joker with the most games already played, chosen at random if tied. If no joker is available, the tool stops and asks you to nominate one.
  • Pair cost: each possible pair gets the cost (|TGoR difference| + club_penalty if same club)². Pairs who already played each other in this tournament, including forfeited games, are excluded.
  • Optimal pairing: the blossom algorithm (maximum weight matching) chooses the pairing with the smallest total cost. Squaring the cost prefers several medium differences over a single very uneven pair.
  • No pairing possible: if rematches make a complete pairing impossible (possible with very few players), the tool stops. Pair the problematic players by hand as manual boards and run it again.

6.3 Handicap, komi and colours

TGoR differenceFull handicapGame
0 – 500Even game, komi komi_even, colours balanced
51 – 1501Weaker player takes black, no stones, komi komi_handicap
151 – 2502Weaker player black with 2 stones, komi komi_handicap
………
851 and more9Maximum
  • The difference is divided by 100 and rounded, with exact halves rounded down (150 → 1, 151 → 2).
  • With a reduction N, the handicap is min(full, 9) − N, but never below 0. In an h2 tournament the default handicap is therefore at most 7. A result of 1 after the reduction is a handicap-1 game, not an even game.
  • Colours in even games are balanced over the tournament: the player who has had white more often in even games gets black. If both are equal, the colour is drawn at random. Handicap games do not count for the balance.
  • Board order: board 1 is the pair with the highest TGoR. Manual boards are sorted in as well.

7. Entering results and standings

7.1 Results

Enter the result in round_r.ods with an x in one of the three columns between the player names: White win, Draw or Black win.

White winDrawBlack winMeaningRating
xWhite winsrated
xBlack winsrated
xDraw (jigo)rated, ½ point each
x!White wins by forfeit (x! under Black win: Black wins by forfeit)not rated – as if the game had not taken place (but counts as "played" for the rematch rule)
!!Both lose by forfeit
No result yet–

Upper case X and check marks (✓) are accepted as well. Anything else, for example marks in two columns, is reported with the row number.

7.2 Checking results AVAILABLE

gotourney results check 3

Reports boards without a valid result, players appearing twice, players who are not registered for the round, and (as a warning) rematches.

7.3 Standings AVAILABLE

gotourney standings            # all rounds played so far
gotourney standings --round 2  # after round 2

Calculates the TGoR of every player after each round and writes standings.ods, for checking and for announcing the standings between rounds. TGoRs are calculated with full precision and shown rounded to whole numbers.

8. The wall list and the EGD upload AVAILABLE

8.1 Wall list

gotourney wall

Calculates the final TGoR and the places, and writes wall_list.ods. Places are ordered by final TGoR (rounded), then lower starting GoR, then a random draw. A second sheet, TGoR history, shows every player's TGoR after each round. You can still correct the wall list by hand, for example a name spelling. All results must be entered before the wall list can be made.

8.2 EGD result file

gotourney h9                      # writes <tournament code or name>.h9
gotourney h9 -o drachenschlacht.h9

Generates the result file in the EGD's .h9 format from wall_list.ods, so your hand corrections are included. Send this file to the EGD. Header (TC stays empty, the EGD fills it in):

; TC[]
; CL[A]
; EV[21. Schweriner Drachenschlacht]
; PC[DE, Schwerin]
; DT[2026-09-26,2026-09-27]
; HA[h0]
; KM[6.5]
; TM[75]
; CM[(submitted by ...)]
;.

One line per player:

 1 Maekawa Kaku          5d DE  K     4  2543  2611  5+/b    6+/w    3+/w2   2+/w    4-/w     |20633162
  • Place, name (spaces inside a name part become _, e.g. van_den_Broek), rank, country (XX if unknown), club (XXXX if none). Names are spelled as in the EGD.
  • Wins (jigo = ½), starting GoR, final TGoR. There are no McMahon columns.
  • One field per round: opponent's place, + win / - loss / = jigo, /w or /b for the colour, then the handicap (omitted if 0). 0= means not played: joker round, absent, or forfeit.
  • |PIN at the end. Players without a PIN have nothing there.

9. How the ratings are calculated AVAILABLE

The TGoR update follows the EGF rating system as revised in 2021. For a game between A and B (Black receives H handicap stones):

h(H)      = 0 if H = 0, otherwise 100 · (H − 0.5)
            (handicap 1 is worth 50 points, 2 stones 150, 3 stones 250, ...)
β(r)      = −7 · ln(3300 − r − h)
            (h only for the player who receives the stones)
SE_A      = 1 / (1 + exp(β_B − β_A))              expected score of A
con(r)    = ((3300 − r) / 200) ^ 1.6
r_A'      = r_A + k_factor · con(r_A) · (S_A − SE_A)
            S = 1 win, ½ jigo, 0 loss; never below −900;
            the EGD bonus term is not used; komi does not enter the formula

Example with k_factor = 3. In the EGD (k = 1) the changes would be a third of these.

GameExpected score of WhiteResultChange WhiteChange Black
White 2000 – Black 1900, even0.63White wins+22.4−25.2
White 2000 – Black 1900, even0.63Black wins−37.6+42.3
White 2000 – Black 1750, 2 stones0.63Black wins−37.6+49.8

The 2 stones are worth 150 points, so the 250-point game in the last row is rated like a 100-point even game. Lower-rated players have a larger con and gain or lose more points per game. The formula was checked against the reference values of an independent implementation of the EGF system.

10. Editing files by hand

  • Open the .ods files in LibreOffice Calc, change what you need, save in .ods format and close the file.
  • Keep the header row. You may add your own columns (they are ignored), reorder columns, or change formatting. Formatting is lost when a tool rewrites the file.
  • Close the file before running a command that writes it. The tools refuse to write a file that is open in LibreOffice, because one of the two versions would otherwise be lost.
  • Never change a player's ID once rounds have been paired. Round files refer to players by ID.
  • The registration window notices when players.ods changes on disk and reloads it within two seconds.
  • Error messages name the file and row, for example players.ods, row 7: invalid rank 'xx'.
