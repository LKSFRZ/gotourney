1. The tournament format

Instead of McMahon scores, every player has a tournament rating (TGoR):

  • Start: the TGoR starts at the player's current EGD GoR on registration day. Players without a GoR start at the value of their declared rank (1k = 2000, 1d = 2100, 100 points per rank). The director may correct a starting GoR, for example when it is clearly outdated. The starting TGoR is capped at the top bar (default 3 dan = 2300): stronger players all start at the bar.
  • After every round, all TGoRs are updated with the EGD rating formula, with two changes. The formula's con factor is multiplied by the tournament's k-factor, so ratings move faster than in the EGD. The EGD's anti-deflation bonus is not used. All games of a round are rated from the TGoRs before that round.
  • Pairing: players are paired so that the TGoR differences are as small as possible, using the blossom algorithm. Two players never meet twice through automatic pairing, and pairs from the same club are avoided where possible.
  • Handicap: games are played with full handicap by default, one stone per 100 TGoR points of difference. A reduction ("full minus N") can be set. Players may agree on a different handicap for their game.
  • Winner: the player with the highest final TGoR wins. If two players have the same final TGoR, the one with the lower starting GoR ranks higher (the real GoR, not capped at the top bar). If that is also equal, a random draw decides.

All files of one tournament live in one folder:

  <name>.h9           result file for the EGD                     (step 6)

All commands take the option -d <folder> to choose the tournament folder. Without it, the current folder is used. So you can either cd my_tournament once, or add -d my_tournament to every command.

What to do next? Every step ends with a short Next steps list that tells you what to do now, based on the state of the tournament, for example: 
Next steps:
  → Print round_1.pdf (by board) and round_1_alphabetical.pdf (players A-Z) and put them up.
  → When the games begin: gotourney start 1
  → Enter the results in round_1.ods: an x under 'White win', 'Draw' or 'Black win'
  → Check them: gotourney results check 1
The suggested commands can be copied directly (with -d if you work outside the tournament folder). Experienced users can switch the hints off with the environment variable GOTOURNEY_NO_HINTS=1.
Web interface (preview). gotourney web opens a page in your browser (only reachable from your own computer) that shows where the tournament stands and offers a button for the next step: create or open a tournament, pair and start rounds, check results, create standings, wall list, EGD file and award slides. Results are still entered in the round file, which opens in LibreOffice with one click; the page updates itself when you save. The page is available in English and German. Entering results, registration and settings in the browser will follow.

3. Installation

Requirements on every system: Python 3.11 or newer (with Tkinter for the registration window), LibreOffice for editing the .ods files, and the project folder TournamentOrgaTool copied to your computer. An internet connection is needed for the installation and for the EGD lookups. In the examples below the project folder is in your home folder; adjust the path if it is elsewhere.

3.1 Linux

Ubuntu / Debian:

sudo apt install python3 python3-venv python3-tk fonts-dejavu-core libreoffice-calc
cd ~/TournamentOrgaTool
python3 -m venv .venv
.venv/bin/pip install -e .
source .venv/bin/activate        # afterwards 'gotourney' works in this terminal
gotourney --help

Other distributions need the same packages under other names, for example Fedora: sudo dnf install python3 python3-tkinter dejavu-sans-fonts libreoffice-calc, Arch: sudo pacman -S python tk ttf-dejavu libreoffice-fresh.

3.2 macOS

  1. Install Python 3.12 (or newer) with the installer from python.org; it includes Tkinter. The python3 that comes with Apple's developer tools is too old. With Homebrew instead: brew install python@3.12 python-tk@3.12.
  2. Install LibreOffice from libreoffice.org (or brew install --cask libreoffice).
  3. Open the Terminal app and run: 
    cd ~/TournamentOrgaTool
python3 -m venv .venv
.venv/bin/pip install -e .
source .venv/bin/activate
gotourney --help
  4. Fonts: nothing to do. The PDFs use the DejaVu font if it is installed, otherwise Arial Unicode / Arial, which come with macOS. For exactly the same look as on Linux, install DejaVu: brew install --cask font-dejavu.

3.3 Windows

  1. Install Python 3.12 (or newer) with the installer from python.org. In the first installer window tick "Add python.exe to PATH". Keep the option tcl/tk and IDLE selected (it is by default); it is needed for the registration window.
  2. Install LibreOffice from libreoffice.org.
  3. Open PowerShell (or the command prompt) and run: 
    cd $HOME\TournamentOrgaTool          # command prompt: cd %USERPROFILE%\TournamentOrgaTool
py -m venv .venv
.venv\Scripts\pip install -e .
.venv\Scripts\activate
gotourney --help
    If PowerShell refuses to run activate ("running scripts is disabled"), run once Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, or use the tool without activating: .venv\Scripts\gotourney --help.
  4. Fonts: without further steps the PDFs use Arial; the star on the award slides then becomes *. For the full set of symbols install the free DejaVu fonts: download them from dejavu-fonts.github.io, unpack, right-click DejaVuSans.ttf and DejaVuSans-Bold.ttf → Install.
  5. Folder paths use backslashes, e.g. gotourney gui -d C:\Tournaments\SpringCup. Paths with spaces need quotes.

3.4 After the installation (all systems)

  • In every new terminal, activate the environment again (source .venv/bin/activate, Windows: .venv\Scripts\activate) or call the tool with its full path (.venv/bin/gotourney, Windows: .venv\Scripts\gotourney). python -m gotourney works as well once the environment is active.
  • Alternatively, pipx install -e ~/TournamentOrgaTool makes gotourney available in every terminal without activating anything (install pipx first, e.g. sudo apt install pipx, brew install pipx or py -m pip install --user pipx).
  • Run gotourney egd update once to download the EGD player list. It is stored in the folder .cache/gotourney in your home folder (Windows: C:\Users\<name>\.cache\gotourney).
  • Choosing a font yourself: set the environment variable GOTOURNEY_FONT to a .ttf file (optionally followed by the path separator – : on Linux/macOS, ; on Windows – and a bold .ttf). The font must contain the stone symbols ○ and ●; otherwise the next suitable font is used.
  • Updating: replace the project folder with the new version and run the pip install -e . line again. Tournament folders are not affected.
  • For developers: pip install -e '.[test]' (Windows: ".[test]") installs the test tools; pytest runs the tests.

4.1 Language of the PDFs

The printable pairing (round_r.pdf), the standings (standings.pdf) and the award ceremony slides (awards.pdf) are written in the language set in tournament.toml:

[output]
language = "de"                        # en, de, fr or custom
translation_file = "translation.toml"
  • This covers all fixed texts: column headings, "Round", "Award ceremony", place, games won, the default prize titles, ordinal numbers (1st / 1. / 1re) and the date format (2026-09-26 / 26.09.2026 / 26/09/2026). Prize titles you write yourself in [awards] are used as they are.
  • The terminal output, the .ods files and the .h9 file stay in English; the .h9 format is fixed by the EGD.
  • Custom language: set language = "custom" and edit translation.toml. gotourney init writes this file with the German texts as an example; each entry is commented. Keep the placeholders in braces, e.g. {round}; \n is a line break. Exceptions for ordinal numbers go into the [ordinals] section (e.g. 1 = "1re"). Missing entries are taken from English, with a warning.
  • gotourney translation-file writes the example file again (--language en|de|fr to start from other texts, --force to overwrite an existing file).

5. Registering players

5.1 The registration window AVAILABLE

gotourney gui -d my_tournament
  1. Search: type part of the name in the search field. Name parts can be in any order ("anna berg" finds van den Berg Anna) and umlaut spellings are treated alike ("Müller" finds Mueller). Typing digits searches by EGD PIN. Players who are already registered are marked (registered).
  2. Choose a player: press ↓ and Enter, or double-click. Enter in the search field takes the first match. The form is filled with name, rank, GoR, PIN, country and club. The window then fetches the player's latest data live from the EGD and updates the GoR if it changed.
  3. Check and complete the form: untick rounds the player will not play, tick Joker if the player may sit out odd rounds, and add notes. Hints in orange appear under the form for:
    • a PIN that is already registered;
    • a rank and GoR that differ by more than rank_gor_tolerance;
    • a last EGD tournament older than gor_outdated_years, meaning the GoR may be outdated. Correct the GoR field if needed.
  4. Add player (or Enter in a form field) writes the player to players.ods immediately.
  • Players who are not in the EGD: type their data into the form without searching. A rank is enough: the GoR is then taken from the rank.
  • Editing: click a player in the bottom table. The form switches to Edit ID n. Use Save changes or Remove player. New / clear goes back to adding.
  • Check registration runs the registration check (see 5.4).
  • Update EGD list downloads a fresh copy of the EGD player list.
The EGD player list. Searching uses a local copy of the complete EGD player list (about 56,500 players). It is stored in ~/.cache/gotourney/ and downloaded again when it is more than a day old. If there is no internet at the venue, the last downloaded list is used. Run gotourney egd update the evening before the tournament to be safe.

5.2 Registering on the command line AVAILABLE

gotourney players add --pin 12345678                       # everything else from the EGD
gotourney players add --pin 23456789 --gor 2300 --rounds 1-3
gotourney players add --pin 34567890 -x "Fee paid=yes" -x "Age group=U11"
gotourney players add Doe John --rank 5k --club Mus --country DE --joker
gotourney players list
gotourney egd search "mueller a"                           # find a PIN

Options of players add: --rank, --gor, --pin, --country, --club, --rounds (all, none, 1,2,4, 1-3), --joker, --notes, and -x FIELD=VALUE (repeatable) for additional data. Values you give explicitly win over the EGD data.

5.4 Checking the registration AVAILABLE

gotourney players check

Problems are reported at three levels:

  • Errors must be fixed before pairing:
    • the same PIN registered twice;
    • a player with neither GoR nor rank;
    • a round with an odd number of players and no joker. Nominate a joker by marking one of that round's players in the Joker column.
  • Warnings should be checked: rank and GoR far apart, GoR possibly outdated, a player registered for no round, two players with the same name.
  • Info is for your knowledge only, for example which jokers can sit out in odd rounds, or which players start at the top bar.

The command ends with an error status if there are errors, so it can also be used in scripts.

5.5 Refreshing EGD data AVAILABLE

gotourney players sync              # live from the EGD
gotourney players sync --offline    # only the downloaded player list

Fetches the current EGD data for all registered players and reports what changed: name, country, club, EGD GoR and last tournament. The declared rank is never changed. The GoR column (starting TGoR) is only filled when it is empty, so your corrections are never overwritten. Once round 1 has been paired, the starting GoRs are frozen.

5.6 Additional player data AVAILABLE

To record more about each player, for example entry fee, age group, e-mail or T-shirt size, list the fields in tournament.toml. A new tournament starts with two fields, each with a fixed list of values:

[registration]
extra_fields = ["Fee paid", "Age group"]

[registration.field_values]
"Fee paid"  = ["yes", "no"]
"Age group" = ["U7", "U11", "U15", "U19", "Ü50"]
  • Dropdown or free text: a field listed under [registration.field_values] gets a dropdown in the registration window and only accepts these values (an empty value is always allowed). A field that is not listed there is free text. To add an e-mail field, for example, add "Email" to extra_fields and do not give it a value list.
  • The registration window shows the fields below Notes, and the table of registered players shows them as columns.
  • On the command line: -x "Fee paid=yes". Field names and dropdown values are not case-sensitive (-x "age group=u11" is stored as U11); other values are rejected.
  • players check warns about values that are not in the list, e.g. typed by hand into players.ods.
  • players.ods gets one column per field, before Notes.
  • Columns you add to players.ods by hand are treated the same way: they are kept when the tools rewrite the file, and they appear in the window (after a restart) and in the standings.
  • standings.ods lists all additional fields after the TGoR column, so you can, for example, sort or filter the standings by age group.
  • The values never affect the rating. They affect the pairing only if you write a pairing rule for the field (see 6.4).

6. Pairing a round AVAILABLE

6.1 Workflow

  1. Optional – pair some boards yourself first. If you want to fix certain games yourself (for example a rematch, or players who must play early), run gotourney pair 3 --template. It creates an empty round_3.ods. Enter those boards with the two player IDs and mark them x in the Finalized column; a board number is optional. The sheet Participants lists the players of the round with their TGoR to help you. If you leave Handicap empty, the default handicap, komi and colours are filled in (White and Black may be swapped so that the weaker player gets black). If you enter a handicap, your colours and handicap are kept as they are. Such boards may be rematches; you get a warning.
    Names instead of IDs: you may leave an ID empty and type the player's name, or part of it, into the White or Black column instead, e.g. Becker, becker a, Müller (also finds Mueller) or just the first name. pair then looks the player up and asks for confirmation: 
    row 2, White: 'fischer' -> Fischer Carl (1d, ID 3, Mus)? [Y/n]: y
row 3, White: 'Becker' matches several players:
  1) Becker Anna (5d, ID 1, Mus)
  2) Becker Bernd (3d, ID 2, Mus)
Which player? (1-2, 0 = cancel) [1]: 2
    Players registered for the round and not yet on another board are preferred. Rows with names count as finalized even without the x. gotourney pair 3 --yes accepts unambiguous matches without asking; ambiguous names then stop with a list. The IDs are written into the round file.
  2. Automatic pairing: gotourney pair 3 keeps all boards marked x in the Finalized column and pairs all remaining players of round 3. Boards without the mark are paired again, so running pair twice gives a fresh pairing. Finalized boards keep their board number; the other boards are sorted by TGoR and get the free numbers.
  3. Check and print. pair also writes round_3.pdf, a printable pairing with only the board numbers, the players (colour stone, rank, name), the result columns and the handicap, ready to post or to collect results on paper. It also writes round_3_alphabetical.pdf: all players of the round sorted by surname, each with board, colour, opponent and handicap, so that everybody finds their board quickly; players who sit out (e.g. the joker) are listed as "does not play this round". Players may agree on a different handicap; just change the Handicap/Komi cells of that board in round_3.ods. The tools always use what is written in the file. After editing the pairing by hand, run gotourney pairing-pdf 3 to update both PDFs.
  4. Start the round: gotourney start 3 finalizes all boards (see 6.2).
gotourney pair never changes a finalized board, not even with --force. If a board that is not finalized already has a result, pair stops; run gotourney start first, or use --force to pair such boards again (their results are lost). A round can only be paired when all results of the previous rounds are entered, and not after a later round exists.

6.2 Starting a round and latecomers

gotourney start 3

When the round begins, start marks every board of round_3.ods as finalized (x in the Finalized column). From then on the pairing of these boards is fixed: board numbers, colours, handicap and results entered so far never change again.

Players who arrive late can still play the round:

  1. Register them for round 3: tick round 3 in the registration window, or put an x in their R3 column of players.ods. gotourney results check 3 lists registered players who are not paired yet.
  2. Run gotourney pair 3. It keeps all finalized boards and pairs only the latecomers among each other, with the usual rules (no rematches, pairing rules, handicap). The new boards get the next board numbers; the command names them, and both pairing PDFs are written again.
  3. When the new games have started, run gotourney start 3 again to finalize them as well.

With an odd number of latecomers one of them cannot play: the joker rule applies (a latecomer marked as joker sits out). If none of them is a joker, the tool stops; mark one as joker, or pair a latecomer by hand against a player who has not started yet.

6.3 How the automatic pairing works

  • Participants: the players with an x in this round's column who are not on a finalized board.
  • Odd number of players: one joker sits out, namely the joker with the most games already played, chosen at random if tied. If no joker is available, the tool stops and asks you to nominate one.
  • Pair cost: each possible pair gets the cost (|TGoR difference| + points of the pairing rules that apply)² (see 6.4; by default 150 points for two players of the same club). Pairs who already played each other in this tournament, including forfeited games, and pairs forbidden by a rule are excluded.
  • Optimal pairing: the blossom algorithm (maximum weight matching) chooses the pairing with the smallest total cost. Squaring the cost prefers several medium differences over a single very uneven pair.
  • No pairing possible: if rematches make a complete pairing impossible (possible with very few players), the tool stops. Pair the problematic players by hand as finalized boards and run it again.

6.4 Pairing rules

Pairing rules use the player columns to make some pairs more expensive or impossible. They are set in tournament.toml. A new tournament has one active rule, the club rule; the other examples in the file are commented out (off):

[[pairing.rules]]
field  = "Club"
type   = "avoid_same"
points = 150

# children (U7, U11, U15) preferably play other children (switched off)
# [[pairing.rules]]
# field  = "Age group"
# type   = "prefer_same"
# points = 200
# values = ["U7", "U11", "U15"]
KeyMeaning
fieldClub, Country, Rank or an additional field (5.6), e.g. Age group.
type = "avoid_same"Players with the same value: the pair counts as points more TGoR difference.
type = "prefer_same"Players with different values: the pair counts as points more TGoR difference.
type = "forbid_same"Players with the same value are never paired automatically (e.g. a Family field).
type = "require_same"Players with different values are never paired automatically.
valuesOptional. These values form one group and count as the same value; all other values together form "the rest". With the example above, children play each other freely (U11 against U15 costs nothing), a child against an adult costs 200 points, and adults among themselves (including Ü50) are not affected.
groupsOptional, instead of values: several groups, e.g. [["U7", "U11"], ["U15", "U19"]]. Values in the same group count as the same; values in different groups, or one in a group and one outside, count as different. A value may only be in one group.
  • Empty cells: for avoid_same and forbid_same an empty cell never counts as "the same" (two players without a club are not in the same club). For prefer_same and require_same two empty cells count as the same value (two adults without an age group).
  • Groups with avoid_same / forbid_same: the rule then only applies inside a group, and values of one group count as the same. groups = [["HH", "HHA"]] on the Club field treats the two clubs as one and ignores all other clubs.
  • Values are compared without regard to case or surrounding spaces.
  • How many points? The points are added to the TGoR difference, so 200 points means "a child against an adult is as bad as a 200-point difference". A higher value makes the rule stronger, but the pairing will then accept larger rating differences to satisfy it. A simulated tournament helps to find a good value.
  • To switch a rule off, delete it or put # in front of its lines. With no rule at all, the pairing uses only the TGoR difference.
  • gotourney pair reports how many boards each rule applies to. Finalized boards may break rules; you get a warning for forbidden pairs.
  • Too many hard rules (forbid_same, require_same) can make a complete pairing impossible; the tool then stops and asks for boards paired by hand.

6.5 Handicap, komi and colours

TGoR differenceFull handicapGame
0 – 500Even game, komi komi_even, colours balanced
51 – 1501Weaker player takes black, no stones, komi komi_handicap
151 – 2502Weaker player black with 2 stones, komi komi_handicap
………
851 and more9Maximum
  • The difference is divided by 100 and rounded, with exact halves rounded down (150 → 1, 151 → 2).
  • With a reduction N, the handicap is min(full, 9) − N, but never below 0. In an h2 tournament the default handicap is therefore at most 7. A result of 1 after the reduction is a handicap-1 game, not an even game.
  • Colours in even games are balanced over the tournament: the player who has had white more often in even games gets black. If both are equal, the colour is drawn at random. Handicap games do not count for the balance.
  • Board order: board 1 is the pair with the highest TGoR. Finalized boards with a board number keep it; the other boards get the free numbers in this order.

7.1 Results

7.2 Checking results AVAILABLE

gotourney results check 3

Reports boards without a valid result, players appearing twice, players who are not registered for the round, and (as a warning) rematches.

7.3 Standings AVAILABLE

gotourney standings            # all rounds played so far
gotourney standings --round 2  # after round 2

Calculates the TGoR of every player after each round and writes standings.ods, for checking and for announcing the standings between rounds. Additional player data (5.6) is included as extra columns.

It also writes standings.pdf for printing or posting, in the language set in [output] (landscape A4): place, name, rank, TGoR with its change since the start, and one column per round showing whom the player played. A round cell such as ○12+ means "white against the player on place 12, won", ●3− (2) "black against place 3 with 2 handicap stones, lost"; = is a jigo, ! a forfeit, ? a missing result and – a round not played. A legend under the table explains this. Additional fields are not shown in the PDF. TGoRs are calculated with full precision and shown rounded to whole numbers.

8. The wall list and the EGD upload AVAILABLE

8.1 Wall list

gotourney wall

Calculates the final TGoR and the places, and writes wall_list.ods. Places are ordered by final TGoR (rounded), then lower real starting GoR, then a random draw. A second sheet, TGoR history, shows every player's TGoR after each round. You can still correct the wall list by hand, for example a name spelling. All results must be entered before the wall list can be made.

8.2 EGD result file

gotourney h9                      # writes <tournament code or name>.h9
gotourney h9 -o spring_cup.h9

Generates the result file in the EGD's .h9 format from wall_list.ods, so your hand corrections are included. Send this file to the EGD. Header (TC stays empty, the EGD fills it in):

; TC[]
; CL[A]
; EV[Spring Go Cup 2026]
; PC[DE, Sampletown]
; DT[2026-09-26,2026-09-27]
; HA[h0]
; KM[6.5]
; TM[75]
; CM[(submitted by ...)]
;.

One line per player:

 1 Becker Anna           5d DE  Mus   4  2480  2412  5+/b    6+/w    3+/w2   2+/w    4-/w     |12345678
  • Place, name (spaces inside a name part become _, e.g. van_den_Berg), rank, country (XX if unknown), club (XXXX if none). Names are spelled as in the EGD.
  • Wins (jigo = ½), starting GoR (the real GoR, not capped at the top bar), final TGoR. There are no McMahon columns.
  • One field per round: opponent's place, + win / - loss / = jigo, /w or /b for the colour, then the handicap (omitted if 0). 0= means not played: joker round, absent, or forfeit.
  • |PIN at the end. Players without a PIN have nothing there.

8.3 The award ceremony AVAILABLE

gotourney awards                 # writes awards.pdf
gotourney awards -o ceremony.pdf

Creates a presentation (16:9 PDF, for a projector) with a title slide and one slide per prize winner: the prize, the player's name, rank, club and country, and place, wins and TGoR. Show it in full-screen mode with any PDF viewer. The command also lists the winners in the terminal. All results must be entered first.

The prizes are set in the [awards] section of tournament.toml. The slides follow the order of the prizes, so you can go from special prizes to 3rd, 2nd and 1st place. A new tournament starts with these prizes:

[awards]
title_slide = true

[[awards.prizes]]
type     = "wins"
min_wins = 5                      # the number of rounds

[[awards.prizes]]
type   = "best_in_group"
field  = "Age group"
values = ["U7", "U11", "U15"]
title  = "Best child"             # "Bestes Kind" with --language de

[[awards.prizes]]
type   = "place"
places = [3, 2, 1]
typeWho gets the prizeSettings
placeThe players on these final places, in the given order.places = [3, 2, 1]
winsEverybody with at least this many wins (jigo = ½), in order of place.min_wins = 4
best_in_groupThe best placed player(s) of a group, e.g. the strongest child. With groups, one prize per group.field, values = [...] (one group) or groups = [[...], [...]], count = 1
rating_gainThe biggest TGoR gain (final TGoR minus starting TGoR).count = 1
  • title is the slide heading. Without a title, a default in the output language is used (e.g. "3rd place" / "3. Platz", "5 wins" / "5 Siege"). A title may contain {place}, {ordinal} (1st, 2nd, ... in the output language), {wins}, {games}, {group} and {n} (1, 2, ... within the prize), e.g. title = "All {games} games won".
  • exclusive = true skips players who already received an earlier prize (earlier in the list), e.g. so that the tournament winner does not also get the prize for the biggest gain.
  • A prize that nobody qualifies for (e.g. nobody won all games) is skipped with a note.
  • "Best" means best placed in the final standings, i.e. highest final TGoR.
  • Club names: the slides show the club's full name instead of the EGD code where it is known, e.g. Köln for K or Badischer Go-Verein e. V., Klub Karlsruhe for BGV1. The list of about 500 clubs in Germany, Switzerland, the UK and Luxembourg comes with the tool (taken from the club name list of the Karlsruher Go-Turnierhandbuch, info.go361.eu/wiki/EGD-Clubnamen). Unknown clubs keep their code. To add or correct clubs, e.g. French ones, put a clubs.csv into the tournament folder: 
    # my clubs
country,code,name
FR,67SE,Strasbourg - Collège Saint-Étienne
DE,K,Go-Club Köln
    Entries there override the built-in list (optional columns: city, region).

9. How the ratings are calculated AVAILABLE

The TGoR update follows the EGF rating system as revised in 2021. For a game between A and B (Black receives H handicap stones):

h(H)      = 0 if H = 0, otherwise 100 · (H − 0.5)
            (handicap 1 is worth 50 points, 2 stones 150, 3 stones 250, ...)
β(r)      = −7 · ln(3300 − r − h)
            (h only for the player who receives the stones)
SE_A      = 1 / (1 + exp(β_B − β_A))              expected score of A
con(r)    = ((3300 − r) / 200) ^ 1.6
r_A'      = r_A + k_factor · con(r_A) · (S_A − SE_A)
            S = 1 win, ½ jigo, 0 loss; never below −900;
            the EGD bonus term is not used; komi does not enter the formula

Example with k_factor = 3. In the EGD (k = 1) the changes would be a third of these.

GameExpected score of WhiteResultChange WhiteChange Black
White 2000 – Black 1900, even0.63White wins+22.4−25.2
White 2000 – Black 1900, even0.63Black wins−37.6+42.3
White 2000 – Black 1750, 2 stones0.63Black wins−37.6+49.8

The 2 stones are worth 150 points, so the 250-point game in the last row is rated like a 100-point even game. Lower-rated players have a larger con and gain or lose more points per game. The formula was checked against the reference values of an independent implementation of the EGF system.

10. Editing files by hand

  • Open the .ods files in LibreOffice Calc, change what you need, save in .ods format and close the file.
  • Keep the header row. You may add your own columns (they are ignored), reorder columns, or change formatting. Formatting is lost when a tool rewrites the file.
  • Close the file before running a command that writes it. The tools refuse to write a file that is open in LibreOffice, because one of the two versions would otherwise be lost.
  • Never change a player's ID once rounds have been paired. Round files refer to players by ID.
  • The registration window notices when players.ods changes on disk and reloads it within two seconds.
  • Error messages name the file and row, for example players.ods, row 7: invalid rank 'xx'.
